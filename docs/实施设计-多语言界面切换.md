# 多语言界面切换 · 设计

作者：yswenli + Agent　日期：2026-11-27　状态：待评审

## 1. 意图

浏览器端（`LubanAgentWebHost` 托管的 SPA）目前只有中文界面。用户希望顶栏能切换界面语言，覆盖 14 种：`en / az / es / id / it / ja / ko / pt / pl / ru / th / tr / zh-CN / zh-TW`。语言入口放在主题切换按钮与用户按钮之间，点击弹出下拉菜单；选择结果存进账号，换设备登录后自动沿用。

为什么现在做：这套工作台已开始给非中文同事与外部合作方使用，界面语言是让"看得懂"变成"用得下去"的最短路径；同时中文文案散落在 47 个文件里，越晚收敛成本越高。

## 2. 目标

- 顶栏语言按钮 + 下拉菜单，14 种语言全量可切；当前项打勾并高亮。
- 切换后界面文案、日期时间、数字与单位即时变化，无需刷新。
- 已登录用户的选择写入账号（`ai_user.Language`），跨设备同步。
- 未登录也能切；匿名选择只落本机缓存，不写账号。
- 首次绘制前就确定语言，避免中文闪一下再变。
- 文案键以语义命名（`chat.clearMessages`），不把中文当键。

## 3. 非目标

- 不要求 AI 回复跟随界面语言；系统提示与模型输出仍由用户输入决定。
- 不翻译后端返回的中文错误与提示（`AuthException.Message` 等），本轮保持中文。
- 不改 `LubanAgentCli`（TUI）、`LubanAgentCodex`（桌面端）的语言。
- 不改 `LubanAgent.Plugin.YunXiao/web` 插件页的文案。
- 不做"跟随系统"选项，也不做按浏览器语言自动切换的开关——首次访问按浏览器匹配，之后以用户选择为准。

## 4. 反目标（技术上能做，但算失败）

- 切换语言触发整页刷新，或导致流式回合中断、滚动位置丢失。
- 引入第三方 i18n 库（i18next / vue-i18n 之类）只为 14 个静态词表。
- 语言包懒加载造成切换时的空白或英文闪烁。
- 用中文原文当键，导致改文案就要改代码与 14 份词表。
- 语言代码写死在前后端两处却互不校验，用户在界面上选得到、服务端存不进去。

## 5. 约束

- 前端是 SolidJS + Vite，无 UI 框架；样式全手写在 `web/src/styles.css`。
- 静态资源由 `web/` 构建后落到 `LubanAgentWebHost/wwwroot`，由 csproj 整体拷贝；新增文件必须走 Vite 产物。
- 后端为 SAEA.MVC + SqlSugar，用户表 `ai_user` 由 `CodeFirst.InitTables` 幂等建表 / 补列，无独立迁移脚本。
- `AuthUserDto` 是登录、注册、状态查询共用的用户模型，新增字段会同时影响三个响应。
- Windows 不支持国旗 emoji，语言菜单不能直接用 `🇬🇧` 这类字符。

## 6. 用户已定的决策

- 语言清单严格为上述 14 种，不提供"跟随系统"。
- 语言按钮放在主题切换与用户按钮之间。
- 偏好存账号，跨设备同步；匿名与老用户默认取浏览器语言，不自动写账号。
- 英文用英国旗、葡萄牙语用葡萄牙旗、繁體中文用「繁」字徽标，其余用内置 SVG 国旗。
- 译文由 Agent 生成、用户审阅。
- 登录页 / 未登录状态也要有语言入口。
- 分两批交付：先做基础设施与全量文案迁移，再补齐其余 13 种语言。

## 7. 我按常见做法定的（未经用户逐条确认，可推翻）

- 语言字段直接加在 `ai_user` 上（可空），而不是单独建偏好表：只有一个值，单独建表反而多一次查询。
- 新增独立接口 `POST /auth/updateLanguage`，不改造 `updateProfile`：后者已被改密流程复用，混在一起会让"只改语言"也触发重新登录。
- 服务端维护 14 种白名单并做大小写归一化；注册时非法 / 空语言按未设置处理，不让注册失败。
- 前端自建轻量 i18n，不引第三方库；`zh-CN` 作为键与类型的唯一真源。
- 语言包全部静态引入：14 份词表压缩后体积可接受，换来切换零延迟与首屏不闪。
- `localStorage['luban.web.locale']` 只作首屏缓存与匿名选择，账号字段才是跨设备真源。
- 后端返回的中文错误暂不翻译（见非目标）。

## 8. 方案比选

| 方案 | 取舍 |
|------|------|
| 引入 i18next / solid-i18next | 功能全（懒加载、命名空间、插件），但为 14 个静态词表引入运行时与额外配置，收益不匹配 |
| 手写 `t()` + 静态词表（采用） | 约 60 行核心逻辑；`satisfies Record<MessageKey, string>` 让缺键在编译期报错；切换同步、无加载态 |
| 语言包懒加载 | 首包小，但切换要等网络，且首屏可能先出中文；本轮不采用 |
| 语言存 `localStorage` | 简单，但换设备不同步，不满足"偏好存账号" |
| 语言存账号并加本地缓存（采用） | 首屏用缓存，登录后由账号覆盖；两处职责清晰 |

## 9. 实现要点

### 9.1 后端

- `DbAgentUser.Language`：`varchar(16) null`，空表示"沿用浏览器语言"。`DatabaseInitializer.EnsureAuthTables` 已有的 `InitTables<DbAgentUser, DbInviteCode>()` 会幂等补列。
- `SupportedLanguages`：14 种代码的白名单与 `TryNormalize`（大小写不敏感）。
- `UserAuthService.RegisterAsync`：合法语言写入，非法 / 空按 `null` 处理。
- `UserAuthService.UpdateLanguageAsync`：白名单外返回 400「界面语言不受支持」；值未变时不写库。
- `WebAuthService.UpdateLanguageAsync` + `AuthController.UpdateLanguage`：薄封装，沿用现有 `RunGuardedAsync` 与 `FailJson` 约定。
- `AuthUserDto.Language`：登录、注册、`/auth/status` 一并返回，前端据此覆盖本地缓存。

### 9.2 前端 i18n

- `i18n/index.ts`：`LOCALES`、`LOCALE_META`、`normalizeLocale`、`matchBrowserLocale`、`t()`、`applyLocale`、`applyAccountLocale`。
- 回退链：当前语言 → 英文 → 简体中文 → 键名。14 份词表齐全后，回退只在将来漏译时兜底。
- `t(key, params)`：占位符统一写成 `{name}`，参数仅接受 `string | number`；可空字段调用方补 `?? ''`。
- 带单位的数量（时长、文件大小、天）交给 `Intl.NumberFormat({ style: 'unit' })`，单复数与语序由浏览器按语言处理；句子里的 `{count}` 用中性语序（如「消息数：{count}」），不拆分复数类别（见 §11）。
- 切换时同步 `document.documentElement.lang`，供浏览器断词、字体与读屏使用。

### 9.3 语言入口

- `components/LocaleMenu.tsx`：`icon`（顶栏）与 `text`（登录页、账号页）两种形态；菜单用统一的 `PopMenu` 贴右边缘展开。
- `components/TopBar.tsx`：顺序为「用户按钮 → 语言按钮 → 主题按钮」，即语言位于两者之间。
- `components/LoginPage.tsx`：卡片右上角常驻语言入口；注册时把当前语言一并提交。
- `pages/settings/AccountTab.tsx`：账号页提供只读展示 + 同一入口；管理员用户列表不展示语言。
- `i18n/flags.tsx`：14 个内置 SVG 图案；English 用英国旗、Portuguese 用葡萄牙旗、繁體中文用「繁」字徽标。

### 9.4 首屏与格式化

- `index.html` 内联脚本在首绘前按 `localStorage` → 浏览器语言 → `zh-CN` 的次序写 `<html lang>`，规则与 `normalizeLocale` 保持一致。
- `lib/format.ts` 的日期、相对时间、数字、紧凑数字、时长单位全部改走 `Intl`，随界面语言变化。
- Markdown 渲染在 `createEffect` 里读取 `locale()`，切语言后重新渲染缓存内容，而不是只换外壳。

### 9.5 质量闸门

- `npm run i18n:check`：校验 14 份词表键集、键序、空值与 `{占位符}` 完全一致，缺一份就退 1。
- `npx tsc --noEmit`：`satisfies Record<MessageKey, string>` 在编译期拦住缺键。
- `npm run build`：产物落到 `wwwroot`，确认新增词表进入打包。

## 10. 验收

- 顶栏语言按钮在主题与用户按钮之间，点击可选 14 种语言并打勾。
- 选择任一语言，顶栏、会话列表、对话页、设置各页签、插件页与登录页文案全部切换，无残留中文。
- 刷新后语言保持；换浏览器 / 换设备登录同一账号，语言跟随账号。
- 未登录切换语言不产生账号写入；注册后账号语言与注册时界面一致。
- 日期、相对时间、千分位、单位（时长、文件大小、天）随语言正确变化。
- `npx tsc --noEmit`、`npm run i18n:check`、`npm run build`、`dotnet build LubanAgent.slnx`、`dotnet test LubanAgent.Tests\LubanAgent.Tests.csproj` 全绿。

## 11. 风险与未决

- 译文质量：14 种语言由模型生成、人工审阅；专业术语（token、MCP、权限模式）先按英文保留。
- 复数类别：句子型 `{count}` 文案未按 `.one/.few/.many` 拆分，个别语言在"数量为 1"时可能仍是复数形式（如英文 `1 messages`）；带单位的数量已用 `Intl.NumberFormat` 规避。若后续要求更严格，可为这类键补复数变体并恢复 `Intl.PluralRules` 选择。
- 窄屏：14 项菜单在手机上有滚动，已限制 `max-height: 420px`；后续可改两列。
- 老用户：`Language` 为空时每次登录都按浏览器语言，符合预期；若将来要"记住浏览器检测结果"，再加一次静默写回即可。
- 新增语言的维护成本：`LOCALES`、`LOCALE_META`、14 份词表、`SupportedLanguages` 与 `i18n/check.mjs` 需同步，已在文件头注释中互相引用。

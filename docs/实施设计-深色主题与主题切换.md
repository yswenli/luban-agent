# 深色主题与主题切换 · 设计

作者：yswenli + Agent　日期：2026-11-19　状态：待评审

## 1. 意图

浏览器端（`LubanAgentWebHost` 托管的 SPA）目前只有一套浅色外观。用户希望顶栏右上角的常驻版本号 `v2.8.1` 换成一个调色板图标，点击后在「跟随系统 / 深色 / 浅色」之间切换；切到深色时**整窗**变暗——顶栏标签、左侧栏、会话正文、输入区、代码块、表格、弹窗、浮层菜单，以及嵌在同源 iframe 里的插件页（云效工作台）。

为什么现在做：夜间在 IDE 旁开这个窗口，浅色底刺眼；版本号又是常驻但几乎没人需要的信息，占着顶栏最显眼的位置。

## 2. 目标

- 顶栏版本号 → 调色板图标按钮；点击弹出三项菜单，当前项打勾并高亮。
- 深色覆盖宿主全部界面与云效插件页，不留白底块。
- 默认「跟随系统」，系统在明暗间切换时页面即时跟随，无需刷新。
- 选择记在浏览器本地，刷新、重开标签后保持。
- 首次绘制前就应用主题，不出现浅色闪屏。

## 3. 非目标

- 不做自定义强调色、多套深色、高对比度/护眼模式。
- 不改 Avalonia 桌面端（`LubanAgentCodex`）、TUI（`LubanAgentCli`）的配色。
- 不把主题写进服务端配置（`appsettings.json` / `webhost.json`），不做多设备同步。
- 不改服务端渲染的 401 / 文件错误页（它们已用 `color-scheme: dark|light dark` 跟随系统）。

## 4. 反目标（技术上能做，但算失败）

- 深色下出现任何白底闪屏或残留白块（代码块、表格、下拉、二维码，以及文件预览里作为「纸张」的 HTML 区域除外）。
- 切换主题触发会话重载、滚动位置丢失、流式回合中断。
- 主题实现引入第三方依赖（不要 CSS 框架、不要 icon 包）。
- 浅色模式外观被改动（除顶栏版本号换成图标这一处）。

## 5. 约束

- 前端纯手写 CSS，不引 UI 框架；`web/src/styles.css` 2969 行、约 420 个规则块，已有 325 处 `var(--*)` 引用，改造应**补令牌、清硬编码**，不重写结构。
- SAEA 静态表的 MIME 限制：产物不得有 `.json` / `.webmanifest`，字体不引 woff2。所以主题不能走「多套主题 JSON」路线。
- 静态资源由 `web/` 构建后落到 `LubanAgentWebHost/wwwroot`，由 csproj 整体拷到输出目录；新增静态文件必须走 Vite 产物或 `<Content>` 显式声明。
- 插件页同源、无 `sandbox`（`pages/plugins/PluginPage.tsx:129`），宿主可以直接操作其 `contentDocument`。
- 主题枚举只三种：`follow` / `dark` / `light`。

## 7. 我按常见做法定的（未经用户逐条确认，可推翻）

- 持久化用 `localStorage`，键 `luban.web.theme`，沿用 `stores/tabs.ts:9` 与 `pages/SessionList.tsx:44` 的现有做法；不存在的旧用户一律按 `follow` 处理。
- 图标始终是调色板，不随当前模式变成太阳/月亮（用户点名要调色板图标）。
- 菜单里不重复展示版本号。
- 按钮位置外观沿用现有 `.icon-btn`，与「新建会话」同尺寸同间距。

## 8. 方案比选

### 8.1 主题令牌怎么存

| | A（推荐）覆盖变量 | B 双份样式表 |
|---|---|---|
| 做法 | `:root` 保持浅色令牌，新增 `html[data-theme='dark']` 覆盖同名变量 | 深色另写一份 `dark.css`，整套选择器复制 |
| 代价 | 改 34 处硬编码颜色 + 新增令牌块（含两套滚动条、4 组状态边框色） | 复制 420 个规则块，两份平行维护 |
| 风险 | 漏改的硬编码会在深色下留白块，需逐处核对 | 后续每次改样式都要同步两份，必然漂移 |
| 结论 | 采用 | 否 |

### 8.2 插件页怎么跟随

| | A（推荐）宿主注入属性 | B postMessage 协议 | C URL 参数 |
|---|---|---|---|
| 做法 | 宿主在 iframe `load` 后把 `data-theme` 写到 `contentDocument.documentElement`，主题变化时同步；插件 CSS 加 `html[data-theme='dark']` 令牌覆盖；插件 `index.html` 另加一小段内联脚本自读主题，消掉首帧白闪 | 宿主广播 `postMessage({type:'theme'})`，每个插件挂脚本监听 | iframe `src` 追加 `?theme=dark`，插件读参数 |
| 代价 | 插件页 CSS 加一个令牌块 + `index.html` 约 8 行内联脚本；第三方插件要各自复制这段 | 每个插件都要写监听 + 兜底，第三方插件默认不响应 | 切主题必须重建 iframe（重载、丢状态、闪一下） |
| 风险 | 依赖同源 + 无 sandbox（当前成立，`PluginPage.tsx:129`）；插件若硬编码颜色仍不跟随 | 需要定协议、写文档，插件作者不照做就无效 | 切主题等于重载插件页，反目标 |
| 结论 | 采用 | 不采用（可留作将来第三方插件的公开协议） | 不采用 |

## 9. 实现要点

### 9.1 主题源：`web/src/lib/theme.ts`（新增）

- `type ThemePreference = 'follow' | 'dark' | 'light'`。
- `themePreference`（signal，初始值读 `localStorage`）+ `setThemePreference`（写回并持久化）。
- `resolvedTheme`（memo，`Accessor<'dark' | 'light'>`）：`follow` 时取 `matchMedia('(prefers-color-scheme: dark)')`，其余直接返回。
- `applyTheme()`：把 `document.documentElement.dataset.theme` 设为 `dark|light`，并设 `style.colorScheme`（让原生控件、滚动条、表单默认样式跟着走）。
- `matchMedia` 的 `change` 监听在 `follow` 下生效，切换即时同步；监听器只注册一次，模块加载时建立。
- 导出 `subscribeThemeForFrame(doc)` 供插件页注入：写属性并把当前值同步到传入 `document`。

### 9.2 防首屏闪烁：`web/index.html`

- `<meta name="color-scheme" content="light dark">`（现在是 `light`）。
- `<head>` 内联脚本（无 CSP 限制，宿主未下发 `Content-Security-Policy`）：读 `localStorage['luban.web.theme']`，`follow` 时读 `matchMedia`，立即写 `documentElement.dataset.theme` 与 `colorScheme`。这段逻辑必须与 `theme.ts` 的解析规则完全一致，注释里互相指认。

### 9.3 宿主深色令牌：`web/src/styles.css`

- `:root` 不动，紧跟其后新增 `html[data-theme='dark'] { … }`，覆盖 `--bg / --surface / --surface-2 / --surface-3 / --border / --border-strong / --text / --text-dim / --text-faint / --accent / --accent-hover / --accent-soft / --danger / --danger-soft / --warn / --warn-soft / --ok / --ok-soft / --shadow*`。
- 规模按实测：`styles.css` 2969 行、约 420 个规则块、325 处 `var(--*)`；非 `:root` 的硬编码颜色声明 34 处（其中 6 处 `#fff`、3 处字面 `box-shadow`）。逐处处理如下（行号按改动前）：
  - 滚动条是两套色值，一对令牌覆盖不了：`:92`/`:99`（全局 `#d7dae0`/`#c2c7d0`）→ `--scrollbar-thumb` / `--scrollbar-thumb-hover`；`:646`（`.side-list, .home-scroll` 的 Firefox 简写 `scrollbar-color: #b3b9c4 transparent`）与 `:656`/`:662`（`#b3b9c4` / `#8f97a3`）→ `--scrollbar-thumb-soft` / `--scrollbar-thumb-soft-hover`。漏掉 `:646` 会让 Firefox 深色下仍是浅色滑块。
  - `:368` `.home-side` 的 `#fbfbfb` → 新增 `--surface-side`（浅色 `#fbfbfb`、深色 `#1a1d22`）。不能直接换 `var(--surface-2)`：那会把浅色左栏从 `#fbfbfb` 改成 `#f7f8fa`，违反「浅色逐像素不变」。
  - `:156` `.btn.danger` 的 `#fff` → `var(--surface)`（浅色 `--surface` 就是 `#ffffff`，不产生像素差异；深色下自然变成面板色）。
  - 状态边框不能合并成一个令牌——`:155`（`.btn.danger` `#f2c8c4`）与 `:1289`/`:1409`/`:2126`（`.notice.error`、`.pending-item.error`、`.toast.error`，均为 `#f4c7c2`）是两个不同色值 → `--danger-border` 与 `--danger-border-soft`；`:1283` `#f5e0b8` → `--warn-border`；`:1295`/`:2120` `#bfe6cf` → `--ok-border`；`:249`/`:1375` `#b9c4ff`（`.session-tab.active`、`.composer.focused`）→ `--accent-border`。
  - `:1919` `.about-qr img` 白底**保留**（`:1918` 注释已说明深色下也必须白底黑码）。全站不存在图片查看遮罩规则；`:1541` 是 `.send-btn.stop:hover` 的 `#000`，一并保留（停止按钮悬停黑底在深色下同样成立）。
  - `:984` `.md pre` 的 `#1c1f26` → `--code-bg`（浅色保持不变）。代码块是固定深色块，块内文字 `:993` `#e6e8ef`、`:1007` `#d5d9e2` 与复制按钮半透明白 `:1006`/`:1018` 一并保留；深色下 `--code-bg` 取 `#14171b`（比所在气泡 `#1c1f24` 再暗一档）并保留 1px `--border` 界定边界。
  - 填充型强调色（`.btn.primary` `:143-147`、`.send-btn` `:1524`、`.optimize-btn` `:1557`、`.tag.current` `:2619`）新增 `--accent-fill`：浅色等于 `--accent`（`#3d5afe`），深色取 `#4a63e8`——`#7c93ff` 上放白字只有约 2.8:1，不达 AA；文字/链接的强调色仍是 `#7c93ff`，按钮填充单独降一档以保住白字可读。`--on-accent` 固定 `#ffffff`。
  - `:1741`/`:1985` 蒙层 `rgba(16,20,28,.42)` → `--overlay`，深色下加深。三处字面阴影 `:1370` `.composer`、`:1764` `.dialog`、`:1998` `.settings-panel` 未走 `--shadow*`，一并收进阴影令牌（深色下阴影不显，分层靠 `--border`）。
  - 两类容易误归类、实际保留的：`:600` `.ws-badge` 的白字压在**内联动态工作区色**（`TopBar.tsx:104`）上，不是强调色，保持 `#fff`；`:1562` 是 `.optimize-btn:hover` 的**背景** `#05603a`，属 ok 系列的悬停底色（`--ok-hover`），不是文字令牌。
- 表格、引用块、代码块靠令牌即可（`:1021` `.md blockquote`、`:1028`/`:1035`/`:1042` 表格）；`kbd`、`mark`、tooltip 在 `styles.css` 与 `src` 中都不存在（提示一律走原生 `title`），无需处理；`::placeholder` 只有 `:1477` `.composer textarea` 一条，搜索框 `.searchrow input`（`:678`）没有规则、深色下走 UA 默认，实现时补一条 `color: var(--text-faint)`。

### 9.4 顶栏控件：`web/src/components/TopBar.tsx`

- 删掉 `:137-141` 的版本号块与 `styles.css:320` 的 `.topbar-version` 规则。
- 加 `icon-btn` 按钮（`title="主题"`、`aria-label`），点击开 `PopMenu`；定位复用 `components/PopMenu.tsx` 的 `menuAt(rect, {width, height, align:'end'})`，与现有用法一致。
- 菜单三项，行内结构：图标 + 文案 + 当前项 `check`；用 `menu-item` / `menu-item active` 现有样式，不新造视觉。

### 9.5 图标：`web/src/components/Icons.tsx`

新增 `palette`（调色板，对齐用户给的图标语义）、`monitor`（跟随系统）、`moon`、`sun`。保持「工厂函数返回 JSX」的现有约定与 24 视口 / 1.7 描边参数。

### 9.6 插件页注入：`web/src/pages/plugins/PluginPage.tsx`

- iframe 加 `ref`，`onLoad` 时 `applyThemeTo(contentDocument)`；`createEffect` 订阅 `resolvedTheme()`，变化时再写一次。
- `contentDocument` 可能为 `null`（跨源或未加载完），一律判空直接返回，不抛错。
- 现有代码没有 `ref`/`onLoad`，是本次新增；`PluginPage.tsx:128` 的 `keyed` 会在点「重新加载」时**重建 iframe 元素**，所以注入必须挂在 `onLoad` 上重跑，不能只在首次挂载时做一次。
- 「不改 `src`、不重建」指**主题切换本身**不触发 iframe 重建（切主题只写属性）；用户点「重新加载」时照常重建。
- iframe 空文档阶段（元素已插入、插件文档尚未建立）由宿主 `.plugin-frame { background: var(--surface) }`（`styles.css:2962-2969`）兜底，深色下不会露白。

### 9.7 插件页样式与首帧：`LubanAgent.Plugin.YunXiao/web/`

- `assets/base.css` 有两处 `:root`：第一处 `:11-28`（`--bg/--surface/--surface-sub/--surface-sub-2/--border/--border-strong/--text/--text-sub/--text-weak/--accent/--warn/--warn-soft` + 3 个 radius + 2 个 shadow），第二处 `:240-248`（`--accent-soft/--ok*/--danger*`）。深色令牌块放在第二处之后，取值与宿主同族（页面底 `#16181c`，避免 iframe 与宿主拼色）。
- **必须显式覆盖 `--accent-soft`**：它被 6 处当背景用（`.proj-item:hover/.on` `:547-555`、`.entry:hover` `:689-690`、`.mopt:hover/.on` `:846-851`、`.tab.on` `:1237-1240`），漏掉就是近白块。
- 新增 `--accent-fill`（与宿主同名同值：浅色 `#3d5afe` → 深色 `#4a63e8`）供 `.btn-primary`（`:317-331`）使用，`--on-accent: #ffffff`。否则插件深色主按钮白字只有约 2.8:1，与宿主侧标注不一致。
- 新增 `--toast-bg`：`.toast`（`:264-265`）背景是 `var(--text)` 配白字，深色下 `--text` 会变亮 → 白字压浅底不可读。浅色 `--toast-bg` 取现 `--text` 值，深色取 `#0f1115` 一类深底；`.toast.success/.error` 的 `--ok`/`--danger` 边框同理核对。
- 清掉 10 处硬编码（8 条规则）：`:168` `.chip-warn`、`:1192` `.er-confirm` 的 `#fedf89` → `--warn-border`；`:1077-1079` `.st-run` 的 `#b2ddff`/`#eff8ff`/`#175cd3` → `--info-border`/`--info-soft`/`--info`；`:429` `.field-input:focus` 的 `rgba(61,90,254,.14)` → `--accent-ring`。
- 三处白字 `:320`/`:324`/`:331`（`.btn-primary` 常态/悬停/禁用）→ `var(--on-accent)`；`:331` 的禁用背景是 `--border-strong`，深色下该令牌不能取过亮的灰（取 `#3a4048` 一类），否则白字不可读。
- `--shadow-sm/--shadow-lg`（`:27-28`）是近黑 `rgba(16,24,40,.05/.07)`，深色下投影不可见；深色块改成更黑的 `rgba(0,0,0,.45)`，分层继续靠 1px 边框。
- `index.html` 的 `<head>` 里、`:7` 的 `<link rel="stylesheet">` **之前**加内联经典脚本：读 `localStorage['luban.web.theme']`，`follow` 时读 `matchMedia('(prefers-color-scheme: dark)')`，立刻写 `documentElement.dataset.theme` 与 `style.colorScheme`。经典脚本在解析时同步执行，早于首绘，能消掉插件文档的白闪。脚本用 try/catch 包裹（`localStorage` 可能抛），**catch 分支也必须写 `colorScheme`**（退回 `follow` 的解析结果），否则原生 `<select>`、复选框、`.content`/`.code-pre` 滚动条在深色下仍是浅色。
- 同页补 `<meta name="color-scheme" content="light dark">`（现在没有）。

### 9.8 文件预览里的 HTML：`web/src/components/FilePreviewDialog.tsx` 与 `web/src/styles.css`

- 该 iframe（`FilePreviewDialog.tsx:117`）带 `sandbox=""`，内容是不透明源，宿主注入 `data-theme` 无效，也不打算改 `filePreview.ts` 的 blob 构造。
- `.file-preview-html` 就是 iframe 元素自身的类（`FilePreviewDialog.tsx:118`），没有外层容器；现在它的背景是 `var(--surface)`（`styles.css:1865`）。
- 深色下把该类固定为 `background: #ffffff` 与 `color-scheme: light`，与页面其余部分脱钩；浅色维持现状。
- 需实机确认：`color-scheme` 作用在内嵌 blob 文档的画布上，效果不能只靠静态推断。确定性来源是「iframe 元素本身白底 + 未设底色文档的默认白画布」。若实机仍出现深底（例如文档显式写了 `transparent` 且画布跟随父级），回退为在 iframe 外套一层白底容器。

### 9.9 连带的注释一致性

`LubanAgentWebHost.csproj:14` 的注释写着「顶栏、关于弹窗与 401 页都读程序集版本」，顶栏不再读版本，需改为「关于弹窗与 401 页」。

## 10. 验收

1. 三项都能选中、菜单显示当前项；刷新后选择保持。
2. `follow` 下改系统主题，页面 1 秒内跟随（含插件页）。
3. 深色下逐屏核对无白底残留：首页、会话（含代码块/表格/工具卡片/思考块）、设置各页、插件管理、插件详情、云效插件页（含 toast、主按钮、选中条目、`<select>` 下拉）、各类弹窗、截图遮罩；文件预览里的 HTML 区域允许是白纸，但要能读清。
4. 深色下打开云效插件页、点「重新加载」各 5 次，不出现白底闪帧。
5. 浅色模式与改动前一致（除顶栏）。

## 11. 风险与未决

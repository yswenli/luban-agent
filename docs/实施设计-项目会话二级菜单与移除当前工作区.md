# 项目 → 会话二级菜单 · 设计（含移除「当前工作区」概念）

作者：yswenli + Agent　日期：2026-11-28　状态：已评审（2026-11-28 确认 §16 四项）

## 1. 意图

浏览器端的会话入口目前是「左栏项目列表 + 右栏全量会话列表」：项目只是筛选器，会话不体现归属，用户想找某个项目下的对话要先点项目再在混排列表里认徽标。本轮把左栏改成 **「项目 → 会话」二级菜单**，右栏改为 **选中项目的详情页**；同时把后端 `IWorkspaceManager.CurrentWorkspace` 这个「每用户一个可变的当前工作区指针」彻底删掉，改由各宿主自己持有选中项、按 `workspaceId` 显式传参。

为什么现在做：

- 会话已经全部落 `workspaceId`（`ai_session.WorkspaceId`），前端 `/session/listDetailed` 一次就能拿到归属，二级菜单不需要新增查询接口。
- 「当前工作区」是进程内每用户单例，多标签页、多客户端、插件后台调用会互相改指针；Web 端切换项目时还会顺带恢复最近会话，导致「看一眼项目就换了活动会话」。这是近期多起串会话/串目录问题的共同根源。
- 越晚删，依赖它的管理服务与宿主越多（当前 41 个非测试文件）。

## 2. 目标

- 左栏：项目行可展开/收起，展开后列出该项目最近 8 条会话；每项显示标题、相对时间、hover「更多」（重命名/删除）；超过 8 条显示「查看全部」。
- 左栏：支持同时展开多个项目，展开集合写入 `localStorage`，刷新后恢复。
- 左栏：搜索框同时匹配项目名与会话标题；命中会话时自动展开其项目并只显示命中项。
- 右栏：只显示当前选中项目的详情与该项目全部会话；移除右栏搜索框。
- 首页（`#/`）默认选中第一个项目；没有项目时给出「新建项目」空态。
- 顶栏「＋」在选中项目下新建会话；未选项目时禁用并提示。
- 收起态（56px）与窄屏（≤760px 横排 chip）不展示二级菜单。
- 后端：`IWorkspaceManager` 不再持有当前工作区；所有写操作/查询按显式 `workspaceId` 工作。

## 3. 非目标

- 不改知识库页（`#/wiki`）的工作区选择逻辑，知识库工作区（`WorkspaceTypes.LlmWiki`）仍不进项目树。
- 不重做 CLI（TUI）与 Codex（桌面端）的界面；本轮只把它们对「当前工作区」的依赖改成宿主本地选中态，交互保持原样。
- 不引入树形组件库，不改现有 SolidJS + 手写 CSS 的形态。
- 不做会话跨项目拖拽；会话归属只在创建时确定，旧「未归属」会话另见 §11.11。
- 不改「项目排序」的存储格式与拖拽手感。

## 4. 反目标（技术上能做，但算失败）

- 为了保留兼容而新增一个 `ICurrentWorkspaceService` / `IWorkspaceSelection`，把刚删掉的指针换个名字装回去。
- 前端继续调用 `/workspace/switch` 或读取 `bootstrap.currentWorkspaceId`，只是把「当前」藏进前端缓存。
- 二级菜单每次展开都请求一次会话列表；`/session/listDetailed` 已经在首屏拉全量。
- 用 DOM 嵌套选择器（`.side-item .side-item`）实现会话行，导致拖拽槽位把会话算进项目顺序。
- 删除「当前工作区」时顺手重构无关模块或改表结构。

## 5. 约束

- 后端为 SAEA.MVC + SqlSugar；`ai_session.WorkspaceId` 可空，旧数据存在未归属会话。
- `IWorkspaceManager` 的接口实现有两份：`LubanAgentCore/Services/WorkspaceManager.cs`（本地）与 `LubanAgentCore/Client/HttpWorkspaceManager.cs`（远程镜像），改接口必须同步两份。
- 框架 `IAgentWorkspaceResolver.ResolveAsync(sessionId)` 必须返回非空 `WorkspaceDescriptor`；会话未绑定工作区时当前实现回退到 `CurrentWorkspace`，删除后要有明确替代规则（§11.11）。
- `IWorkspaceContextProvider`（LocalMemory 用）是 scoped 服务，当前实现按 `CurrentWorkspace` 取值；会话 scope 里已有 `DefaultContextState.WorkspaceId`，应改为读它。
- 前端是 SolidJS + Vite，状态集中在 `web/src/stores/app.ts` 的模块级信号；样式全在 `web/src/styles.css`。
- i18n 共 14 份词表，`i18n/check.mjs` 要求键集合与条数完全一致；新增文案必须 14 语言同步。
- 构建产物落在 `LubanAgentWebHost/wwwroot/`，每次前端构建后单独提交。

## 6. 用户已定的决策

- 采用方案 C：左栏项目可展开列出会话；右栏只显示选中项目的会话详情。
- 首页默认选中第一个项目。
- 多项目可同时展开，展开集合持久化。
- 拖拽排序只作用于项目行：项目行用 `.side-item`，会话行用 `.side-session`。
- 收起态与窄屏不展示二级菜单。
- 后端彻底删除 `IWorkspaceManager.CurrentWorkspace` 概念，不是只让 Web 端不依赖。
- 旧会话 `workspaceId` 为空时，左栏加「未归属」虚拟项目节点：不可拖拽/重命名/新建，可打开、可删除。
- 顶栏「＋」落到当前选中项目；未选项目时禁用并提示。
- 知识库工作区会话仍排除，不进项目树。
- **未归属旧会话**：只读历史 + 发送前归属（不建临时根、不批量回填）。
- **落地节奏**：阶段 A / B / C 三次提交。
- **项目行点击语义**：整行点击 = 选中该项目并展开；再次点击已选中行 = 收起（保留选中）。行首另放独立 chevron 只做纯展开/收起。
- **选中项持久化**：记 `localStorage['luban.web.selectedProject']`，失效或不存在时回落第一个项目。

## 7. 实现细节约定（未经逐条确认，评审时可推翻）

- **右栏会话分组**：沿用「今天 / 更早」两段，按 `updatedAt ?? createdAt` 倒序；不做分页。
- **「查看全部」**：选中该项目并把右栏滚动到会话区顶部；不再额外开弹窗。
- **搜索命中规则**：项目名命中 → 该项目及其全部会话都保留；仅会话标题命中 → 只保留命中的会话。搜索期间项目自动展开，清空搜索后恢复用户原来的展开集合。
- **未归属节点排序**：永远排在真实项目之后；不参与 `projectOrder`。
- **会话行「更多」**：左栏二级项与右栏行共用同一套菜单/弹窗代码，抽到 `components/SessionActions.tsx`，避免两份重命名/删除逻辑。
- **后端未归属会话的对话规则**：未绑定项目的旧会话可打开看历史；首次发送前必须「归属到项目」（见 §11.11）。
- **API 缺 `workspaceId` 的口径**：文件读写/附件上传返回 400，不再回退任何「当前」；新建会话返回 400。仅 `/session/listDetailed` 等只读列表不需要 `workspaceId`。

## 8. 方案比选

| 方案 | 取舍 |
|------|------|
| 只改前端：继续 `/workspace/switch`，后端不动 | 改动最小，但多标签页仍会互相改「当前工作区」，且与「彻底删除」目标冲突 |
| 保留 `CurrentWorkspace`，Web 端改为每请求带 `workspaceId` | Web 不受影响，但 CLI/Codex/插件仍共享可变指针，问题只被 Web 绕过 |
| 删除指针 + 各宿主自持选中态（采用） | 语义最干净：同用户多标签、多客户端互不干扰；代价是 41 个文件与 3 个测试假实现要改 |
| 新建 `IWorkspaceSelection` 统一存放选中态 | 本质是改名，不解决跨宿主共享；不采用 |

## 10. 目标架构

### 10.1 所有权

| 概念 | 所有者 | 存储 |
|------|--------|------|
| 项目（工作区）清单 | 后端 `ai_workspace` | 数据库 |
| 会话归属 | 后端 `ai_session.WorkspaceId` | 数据库 |
| Web 选中项目 / 展开集合 | 前端 | `localStorage` |
| CLI 选中项目 | CLI 进程内 | `CliWorkspaceSelection`（新增，仅 CLI 注册） |
| Codex 选中项目 | Codex 进程内 | `MainWindowViewModel.SelectedWorkspace` + `CodexWorkspaceSelection`（新增，仅 Codex 注册） |
| 会话运行时工作区 | 会话 scope | `DefaultContextState.WorkspaceId/RootPath` |

`IWorkspaceManager` 退化为**无状态仓储 + 无状态动作**：查/建/删/改名/授权/确保配置目录/更新活跃时间，不再记「谁被选中」。

### 10.2 后端接口改造

`IWorkspaceManager` 删除：

- `WorkspaceInfo? CurrentWorkspace { get; }`
- `event Action<WorkspaceInfo>? CurrentWorkspaceChanged;`
- `Task SwitchWorkspaceAsync(string workspaceId);`
- `Task SetCurrentAsync(string workspaceId);`
- `bool IsWithinWorkspace(string path);`

新增无状态动作（名字可按评审调整）：

```csharp
/// <summary>取工作区；不存在返回 null。</summary>
Task<WorkspaceInfo?> GetWorkspaceAsync(string workspaceId);

/// <summary>确保配置目录存在并刷新 LastActiveAt；不改变任何「选中」状态。</summary>
Task TouchAsync(string workspaceId);

/// <summary>路径是否位于指定工作区根内；root 为空返回 false。</summary>
static bool IsWithin(string path, string? rootPath);
```

`WorkspaceManager.SwitchWorkspaceAsync` 里的三段副作用拆开：

| 原副作用 | 新归属 |
|----------|--------|
| `_current = newCurrent` + 事件 | 删除 |
| 恢复最近会话 / 清空活动会话 | 调用方（CLI/Codex/Web）显式调用 `SessionBootstrap` 或 `ISessionManager` |
| `EnsureConfigDirectoryAsync` + `UpdateLastActiveAtAsync` | `TouchAsync(workspaceId)` |

`IWorkspaceManagementService`：

- 删除 `GetCurrentAsync`、`SwitchAsync`。
- 新增 `Task TouchAsync(string workspaceId, CancellationToken ct = default)`（供 CLI/Codex 切换时用）。
- `ListAsync`/`CreateAsync`/`DeleteAsync`/`FindByRootPathAsync`/`SearchAsync`/`GrantAccessAsync` 不变。

### 10.3 前端数据流

```
bootstrap.workspaces ──┐
                       ├─→ projectWorkspaces()  (排除 LlmWiki，叠加 projectOrder)
sessions() ────────────┘        │
                                ├─→ sessionsByProject: Map<workspaceId|null, SessionSummary[]>
                                │
selectedProjectId (localStorage)┼─→ 右栏 project detail
expandedProjects  (localStorage)┘─→ 左栏展开态
```

- 不再有 `currentWorkspaceId` 信号，也不再调 `/workspace/switch`。
- 新建会话显式传 `workspaceId: selectedProjectId()`。
- 未归属会话用 `null` 键聚成一个虚拟节点，`workspaceId` 原样传 `null`。

## 11. 实现要点

### 11.1 后端接口与实现

1. `WorkspaceManager.cs`：删除 `_current`/`_currentLock`/事件；`SwitchWorkspaceAsync` 改为 `TouchAsync`（只做配置目录 + `LastActiveAt`）；`SetCurrentAsync` 删除；`RenameAsync` 删除「同步 `_current`」分支；`IsWithinWorkspace` 改为静态 `IsWithin(path, rootPath)`。
2. `HttpWorkspaceManager.cs`：删除镜像属性/事件与两个切换方法；`IsWithin` 改为本地路径判断（不再依赖镜像根）；确认 `GetKnownRootPath` 仍可用（用于同步接口）。
3. `WorkspaceManagementService.cs`：删除 `GetCurrentAsync`/`SwitchAsync`，新增 `TouchAsync`。
4. `ToolConfirmationContextExtensions.cs`：删除 `workspaceManager.IsWithinWorkspace` 回退；只保留 `ISessionContext.IsWithinEffectiveRoot`。无会话上下文时按「不允许」处理。
5. `AttachmentService.cs`：构造参数 `IWorkspaceManager? workspace` 删除；`ResolvePath` 改为要求显式根（或从 `DefaultContextState.WorkspaceRoot` 读）。CLI 的 `InputBarView` 在会话 scope 内解析，可直接用 scope 状态。
6. `AgentHostBuilder.cs`：
   - `DelegateWorkspaceContextProvider` 改为 `() => sp.GetService<DefaultContextState>()?.WorkspaceId`（scoped，会话正确）。
   - `InitializeWorkspaceAsync` 去掉 `reportCurrentWorkspace` 参数与 `SetCurrentAsync`；只返回「已存在/已创建」通知。
7. `CoreSeams.cs`：`CoreWorkspaceResolver` 未绑定工作区不再回退；按 §11.11 的规则返回明确结果或抛可识别异常。

### 11.2 核心管理服务

这些服务的「聚合列表」当前用 `CurrentWorkspace?.RootPath` 作为工作区文件根。统一改为**显式可选根参数**：

```csharp
Task<IReadOnlyList<SkillListItem>> ListAsync(string? workspaceRoot = null, CancellationToken ct = default);
```

- `SkillManagementService`、`RuleManagementService`、`McpManagementService`、`ConnectorManagementService`：`ListAsync` 增加 `workspaceRoot`；为 null 时只合并全局 + config，不猜工作区。
- `SkillCatalogService.ListAvailableAsync(sessionId)`：会话未绑定时只返回全局技能，不回落。
- `LlmWikiManagementService`：缺省 `workspaceId` 改为参数必填（Web 已传）。
- `SqliteVectorStore`：缺省 `workspaceId` 改为空串/明确拒绝，不再读指针。
- 调用方（CLI/Codex 设置页）传入自己的选中工作区根；Web 继续用 `SettingsScope.ResolveAsync` 得到的根。

### 11.11 未归属会话（关键分岔）

问题：`IAgentWorkspaceResolver.ResolveAsync` 必须返回工作区；未归属会话没有 `WorkspaceId`，删除指针后没有根。

建议规则：

1. 左栏「未归属」节点可展开、可打开会话看历史；打开时不触发 Agent 初始化（只读消息），不报错。
2. 输入框在未归属会话中禁用发送，显示提示「该会话未归属任何项目」+ 按钮「归属到当前项目」。
3. 点击归属：把 `ai_session.WorkspaceId` 写成当前选中项目，前端刷新会话列表，会话移入该项目二级菜单；之后可正常对话。
4. 没有选中项目时，「归属」按钮禁用并提示先选项目。
5. 后端 `CoreWorkspaceResolver` 对未绑定会话抛 `InvalidOperationException("会话未绑定工作区")`；Web 的发送接口捕获后返回 409 + 明确文案，而不是 500。

备选（若用户希望「打开即可继续聊」）：为未归属会话建一个隐藏的临时工作区根（如 `~/.luban-agent/unassigned/<sessionId>`），不写入 `ai_workspace`，仅用于本轮工具根。代价是文件链接与记忆归属会落到临时目录，且需要额外清理。**已确认不采用**（2026-11-28 决策记录 #1）。

## 15. 风险与未决

1. **未归属会话的对话规则**（§11.11）：已决定采用「只读历史 + 发送前归属」，不做临时根，因此风险降为「用户需多点一次归属」。
2. **41 个文件的机械改造**：`IWorkspaceManager` 是 Core 公共接口，CLI/Codex/插件/测试都实现或调用；建议阶段 C 单独提交，避免与前端改动混在一起难以定位回归。
3. **`IWorkspaceContextProvider` 的 scoped 生命周期**：改成读 `DefaultContextState.WorkspaceId` 后，必须确认所有解析点都在会话 scope 内；根 scope 解析会拿到 null，需接受「无工作区记忆」而非回退。
4. **`AgentHost.InitializeAsync` 的工作区解析**：会话必须先落 `WorkspaceId` 才能建运行时；新建会话在 `WebSessionService.CreateAsync` 已显式写入，未归属会话按 §11.11 处理。若将来允许「先发消息再建会话」，需要把 `workspaceId` 放进 `AgentRunRequest`。
5. **并发/多标签**：删除指针后，两个标签页可以各自选中不同项目，互不干扰；但同一会话在两标签同时发送仍由现有回合串行机制约束，不在本轮范围。
6. **`SessionClearScope` 语义变化**：删除「当前工作区」维度后，`clearAll` 不再有「未指定就清当前」的默认；设置页调用方必须显式传 `workspaceId` 或 `allWorkspaces: true`，否则 400。需要在设置页确认调用点。
7. **i18n 14 份词表**：新增约 10 个键 × 14 语言，`check.mjs` 会强制键序与占位符一致；建议先改 `zh-CN` 再批量生成，最后跑检查。
8. **构建产物**：`wwwroot` 必须在阶段 A 后单独提交，避免后端改动提交里混入大量 hash 文件。

# 新建项目（newproject-create）

> 本文件由「新建项目」插件（`com.tjces.newproject`）随包分发，宿主加载插件后写入当前工作区
> `.luban-agent/skills/newproject-create/SKILL.md`。
> **M4-P1 骨架版**：触发条件、输入输出与编排顺序已按 PRD §4.3 / §4.10 落地；
> 分步执行脚本与失败引导文案在 **M4-P6** 补齐。

## 何时使用

用户用自然语言表达「新建一个项目」，例如：

- 「新建一个项目，缩写 jnms，要后端和管理后台」
- 「用 TJCES 模板建个项目，名字叫江南管理系统，三端都要」
- 「帮我初始化一个新项目的代码骨架并建好流水线」

## 输入（ProjectSpec，PRD §4.5）

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 项目名称 | 中文名称 | 必填 |
| 英文缩写 | 小写字母开头、可含数字；用于目录 / 仓库名 / 流水线名 | 必填，需唯一 |
| 项目介绍 | 一句话说明，用于项目助手与 README 占位 | 必填 |
| 端选择 | **后端、管理端必选**；移动端可选 | 必填 |
| 本地目录 | 工作区根目录 | 必填 |

信息不全时**逐项追问**，不要替用户假定端选择与本地目录；也可提示用户打开左侧栏「新建项目」向导补填。

## 输出

- 新建项目的本地路径（工作区根目录）
- 各端目标仓库地址与默认分支
- 数据库状态
- 流水线 ID 列表（所选端各 1 条，最多 3 条）

## 编排顺序（七步，PRD §4.3）

1. **基本信息**：向用户收集上表字段（本步不调用后端）。
2. **初始化**：调用共享能力层 `INewProjectService.InitializeAsync`（建工作区 → 授权 → 置为当前 → 装配技能 → 接通云效 → 生成项目助手）。
   新建工作区**必须走新会话**（`SessionRuntimeManager.AllowedRoots` 一次性写入）。
3. **建库**：委托 `newproject-clone-template`。
4. **数据库**：委托 `newproject-setup-db`。
5. **编译**：委托 `newproject-build`。
6. **推送**：委托 `newproject-push-repo`。
7. **流水线**：委托 `newproject-create-pipeline`。

## 分叉规则（重要）

- **云效相关步骤**（3 / 6 / 7）一律编排 `mcp_yunxiao_*` 工具，**不自行拼 REST、不自行实现**（PRD §4.10.7）。
- **纯本地步骤**（2 / 4 / 5）调用共享能力层 `INewProjectService`，与向导面板是同一实例，**零逻辑分叉**。

## 失败与重试

- 单步失败即**停在当前步**，说明原因并给出可选动作（重试 / 换参数 / 中止）。
- 任何步骤都**不得**把 PAT 回显到对话或日志（PRD §4.8 #6/#7/#11）。
- 令牌失效（401）→ 引导用户到 codex 云效配置重新录入 PAT，而不是重试硬闯。
- 中止：走「中止并清理」——注销本项目工作区（**不删**本地目录）、清掉写入的技能与 MCP 文件；
  **远端产物（仓库 / 分支 / 流水线）一律不自动删除**，只列孤儿清单供用户到云效控制台手动确认。

## 与向导的关系

主 skill 是向导的「对话式入口」，两者最终都落到同一个 `INewProjectService`：默认走完整七步；
用户中途打开向导后，也是同一条流程、同一份项目档案。

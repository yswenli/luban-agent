# 新建项目（newproject-create）

> 本文件由「新建项目」插件（`com.tjces.newproject`）随包分发，宿主加载插件后写入当前工作区
> `.luban-agent/skills/newproject-create/SKILL.md`。
> **助手驱动口径**：Step 3 / 6 / 7 的动作全部由**本会话助手**执行——
> 云效侧调 `mcp_yunxiao_*`，git 侧调框架 **git 工具组**（`GitCloneAsync` / `GitPushAsync` 等）；
> 插件只做薄校验、下发提示词、回读结论文件。**组织专有值**（端口 / Harbor / 服务连接 / 模板仓名 /
> 主机组 uuid …）**不在本正文复述**，一律读工作区 `.luban-agent/plugin-newproject/docs/` 下的对应文档
> （索引见 `docs/README.md`）。

## 何时使用

用户用自然语言表达「新建一个项目」，例如：

- 「新建一个项目，缩写 jnms，要后端和管理后台」
- 「用组织模板建个项目，名字叫江南管理系统，三端都要」
- 「帮我初始化一个新项目的代码骨架并建好流水线」

## 输入（ProjectSpec，PRD §4.5）

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 项目名称 | 中文名称 | 必填 |
| 英文缩写 | 只允许小写字母 a-z（不含数字）；用于目录 / 仓库名 / 流水线名 | 必填，需唯一 |
| 项目介绍 | 一句话说明，用于项目助手与 README 占位 | 必填 |
| 端选择 | **后端、管理端必选**；移动端可选 | 必填 |
| 本地目录 | 工作区根目录 | 必填 |

信息不全时**逐项追问**，不要替用户假定端选择与本地目录；也可提示用户打开左侧栏「新建项目」向导补填。

## 输出

- 新建项目的本地路径（工作区根目录）
- 各端目标仓库地址与默认分支
- 数据库状态
- 流水线 ID 列表（所选端各 1 条，最多 3 条）

## 编排顺序（七步，PRD §4.3）

1. **基本信息**：向用户收集上表字段（本步不调用后端）。
2. **初始化**：调用共享能力层 `INewProjectService.InitializeAsync`（建工作区 → 授权 → 置为当前 →
   装配技能 → 接通云效 → 生成项目助手），并把 `docs/**` 复制进工作区
   `.luban-agent/plugin-newproject/docs/`。
   新建工作区**必须走新会话**（`SessionRuntimeManager.AllowedRoots` 一次性写入）。
3. **建库**：委托 `newproject-clone-template`——**一次只读准备下发 + 用户确认后同会话执行续跑**。
4. **数据库探活**：**你亲自执行**（用脚本工具直连库，确认「能连上且库存在」）——见 `newproject-setup-db`。
   只探活：不建库、不写任何项目文件/配置；结论**不阻断**后续步骤。
5. **编译**：**你亲自执行**（逐端编译，编译方式按工程类型判断）——见 `newproject-build`。
   失败**阻断** Step 6。
6. **推送**：委托 `newproject-push-repo`——**一次下发**（云效侧仅只读查证，git 动作走 git 工具组）。
7. **流水线**：委托 `newproject-create-pipeline`——**一次只读准备下发 + 用户确认后同会话执行续跑**。

## 执行方式（助手驱动，重要）

- **云效侧（Step 3 / 6 / 7）**：一律调 `mcp_yunxiao_*` 工具，**不自行拼 REST、不自行实现**（PRD §4.10.7）。
- **git 侧**（克隆 / 分支 / 提交 / 推送）：一律调**框架 git 工具组**——`GitCloneAsync` /
  `GitStatusAsync` / `GitBranchListAsync` / `GitCheckoutAsync` / `GitAddAsync` / `GitCommitAsync` /
  `GitPushAsync` 等。**云效 MCP 已不再提供 git 类工具**，
  克隆地址取自仓库详情里的 `httpUrlToRepo`。
- **git 凭据由用户在外部环境自行配置**（git credential helper / 系统凭据管理器 / 预置 remote）：
  助手与插件都**不拼 `oauth2:<PAT>@` 认证 URL、不注入凭据**；失败时把 git 原文摘要带进结论文件与
  操作记录，并提示「请先在外部环境配好 codeup HTTPS 凭据」。
- **破坏性 git 动作约定**：**不得**使用 `--force` / `reset --hard` / `clean -fd`。
- **初始化（2）** 调共享能力层 `INewProjectService.InitializeAsync`，与向导面板是同一实例，**零逻辑分叉**。
- **Step 4 / 5 由你亲自执行**（脚本工具探活 / 编译）：插件只固定「边界 + 结论文件契约」，不代你干活。
  此时**不要**回头调用「新建项目」插件的技能或服务——若本步是向导下发的提示词，同会话回合会串行自等，
  直接死锁；用户自己发的消息里也请照此办理（技能正文即执行口径）。

## 轮次口径：一次准备 + 执行续跑

Step 3 / 7 统一口径为「**一次只读准备下发 + 用户确认后同会话执行续跑**」。
在宿主 API 上表现为「先下发一次只读准备 → 用户确认 → 再下发一次执行续跑」——
框架没有「轮内提问」工具，答复后由插件再发一次提示词；执行续跑只做增量，**不重跑准备阶段**。

## 结论文件（机器判定口径）

每一步的结论一律落文件（`results/step{N}-*.json`）、不解析对话：

- 路径：`{项目工作区}\.luban-agent\plugin-newproject\results\step{N}-<yyyyMMdd-HHmmss-fff>.json`
- 通用字段：
  - `status`：`done` / `needsInput` / `failed`（**Step 3 / 6 / 7 必填**，且为阻断性判定）；
  - `checks[]`：逐项证据（`name` / `ok` / `detail` / 可选 `command`）；
    Step 5 的 `checks[].name` 必须**逐端写全**（`Service` / `Admin` / `Mobile`），漏端即判失败；
  - `artifacts[]`：产物账目（Step 3 / 6 / 7），元素带**判别属性 `kind`**（`group` / `repository` /
    `pipeline`），每类 `extra` 是**具名强类型**（字段固定、只能填值，不得用自由字典）；
  - `inputs[]`：需用户决策时（`needsInput`）的选项（克隆冲突三选一 / 部署目标选择），
    部署目标选项**必须同时带数字 id 与 uuid**；
  - `message`：人话总结，`failed` 时必填可操作原因。
- 判定：
  - **Step 4 / 5**（判定口径不变）——四环齐：文件存在 + JSON 可解析 + `ok: true` + 本轮事件流无真错误
    （守卫拒绝 / 用户取消**不算**错误）。
  - **Step 3 / 6 / 7**（阻断性）——文件存在 + 可解析 + `status == "done"` 且 `ok == true` +
    本轮无真错误 + 插件侧**本地复核**通过。
- **时效**：插件在每次下发前记录起始时刻，**只认本轮起始时刻之后生成**的结论文件；
  历史文件保留在 `results/`，UI 标注为「历史轮次」，不参与判定。

> 向导路径下，插件会自行发起各步提示词并回读结论文件；聊天路径下你亲自执行、同样落这份文件，便于事后复核。

## 失败与重试

- 单步失败即**停在当前步**，说明原因并给出可选动作（重试 / 换参数 / 中止）；所有「建」动作**先查后建**。
- 任何步骤都**不得**把 PAT 回显到对话或日志（PRD §4.8 #6/#7/#11）；结论文件不得含口令 / token。
- 令牌失效（401）→ 引导用户到 codex 云效配置重新录入 PAT，而不是重试硬闯；403 不重试。
- 云效 429 / 限流 → 按对应 docs 的退避约定重试（**线性 10s / 20s / 30s，最多 3 次**），仍失败即失败。
- git 认证失败 → 提示「请先在外部环境配好凭据」+ git 原文摘要。
- 中止：走「中止并清理」——注销本项目工作区（**不删**本地目录）、清掉写入的技能与 MCP 文件；
  **远端产物（仓库 / 分支 / 流水线）一律不自动删除**，只列孤儿清单供用户到云效控制台手动确认。

## 与向导的关系

主 skill 是向导的「对话式入口」，两者最终都落到同一个 `INewProjectService`：默认走完整七步；
用户中途打开向导后，也是同一条流程、同一份项目档案。
`docs/` 知识随插件包分发、在 Step 2 复制进工作区，是**创建时快照**——
插件升级后的知识更新只对**新建**项目即时生效，已建项目保留其工作区快照。

# 数据库探活（newproject-setup-db）

> 「新建项目」插件原子技能 · 对应 **Step 4** · **M4-P4 已落地**（口径见 PRD §4.3 Step 4，v0.22）。

## 何时使用

- 主 skill `newproject-create` 的第 4 步；
- 或**仅重新探活**（改库名 / 手工建好库后复验）。

## 执行（由你**亲自执行**，不走插件服务）

**本技能要求项目助手在本会话内自己动手**，用脚本工具直连数据库，确认「能连上且该库已存在」：

1. 拿到参数：服务器、端口、库名、账号、口令（向导界面采集，或用户消息里给）。
2. 用 `runpython` **一条命令**跑一段 pymysql 短脚本（连接超时 5 秒），只看连接是否成功；库不存在直接失败。
3. 把结论写进**结论文件**，回复正文只回一行 `DONE` 或 `FAILED: <一句话原因>`。

结论文件路径与 schema 由插件固定，**原样使用、不要另存别处**：

- 路径：`{本地目录}\.luban-agent\plugin-newproject\results\step4-<时间戳>.json`
- schema：

```json
{
  "step": 4,
  "ok": false,
  "checks": [ { "name": "connect", "ok": false, "detail": "<原始错误 / 已连接且库存在>" } ],
  "message": "<一句话结论>"
}
```

> **不要调用** `newproject-*` 技能，也不要调用「新建项目」插件的任何工具或服务：本步的提示词正是该插件在**同一会话**里下发的，
> 回头调用插件服务会形成「同会话回合串行」的自等死锁。

## 硬边界（v0.22 口径）

- **只探活**：不建库、不执行任何 SQL（`CREATE` / `DROP` / `ALTER` / `TRUNCATE` / `INSERT` / `UPDATE` / `DELETE` 一律禁止）。
- **不写项目文件**：不改 `appsettings*.json`、不生成任何配置、不动源码；**唯一允许写的是结论文件**。
- **口令只在内存**：不写进任何文件、不写日志、不复述；结论文件的 `detail` / `message` 里也不得出现口令原文。
- **不阻断**：库不存在就是「未通过」，如实报告即可——**不要替用户建库**，也不要因此拒绝继续后续步骤。

## 结果

- 能连上且库存在 → `ok: true`，操作记录区出现该步时间线条目（动作 / 参数摘要 / 结果 / 耗时）。
- 探活未通过 → `ok: false` + 可操作原因（如 `1049 Unknown database 'xxx'`），**流程照常推进到 Step 5**。

## 失败处理

- `1049 Unknown database`：提示「该库还不存在，请先在数据库里**手工建库**，再回到本步重跑」。
- `1045 Access denied`：核对账号 / 口令 / 授权主机是否匹配。
- `2003` / 连接超时：核对服务器地址、端口、网络与防火墙。
- 任何情况下都**不回显口令**，也不把口令写进日志或结论文件。
